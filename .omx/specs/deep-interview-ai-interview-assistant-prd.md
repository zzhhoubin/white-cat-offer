## Clarified Intent

用户希望在现有 PRD 的基础上继续讨论并完善产品需求，使其从较宽泛的“一站式求职助手”收敛为更适合第一阶段验证和研发评审的产品规格。

核心意图不是一次性实现全部求职闭环，而是先验证产品最有差异化、最可能产生付费价值的能力：线上面试中的实时辅助是否足够有用。

## Desired Outcome

输出一份更收敛、更可执行的 PRD 完善版，重点明确：

1. 第一阶段主线。
2. MVP 范围与非目标。
3. 实时辅助的商业可用验收标准。
4. 面试准备、题库、模拟面试与实时辅助之间的关系。
5. 自动投递等高风险功能的后移安排。
6. 后续研发、设计和测试可以依据的功能边界。

## Key Decisions

### Product Wedge

第一阶段同时保留：

1. A：面试准备闭环。
2. B：实时辅助闭环。

但两者主次关系为：

- 实时辅助是第一阶段核心验证点。
- 面试准备闭环是实时辅助的前置支撑能力。
- 自动投递不进入第一版核心范围。

### MVP Validation Mode

第一版同时验证 A+B，但不是完整大而全产品：

- A 做到能支撑实时辅助所需的个人材料结构化、专属题库和回答模板。
- B 需要接近商业可用体验，作为原型能否继续投入的核心判断依据。

### Primary Success Signal

第一阶段最重要的成功信号是：

> 实时辅助有效性：线上模拟场景中能识别面试问题，并给出用户可采纳的回答提纲。

### Real-Time Assistance Acceptance Level

用户选择“商业可用”作为实时辅助验收标准，即：

1. 低延迟。
2. 高准确率。
3. 回答建议稳定。
4. 适合真实线上面试场景。
5. 输出能够被用户直接转化为口头表达。

## In Scope

第一版应包含：

1. 中文线上面试实时辅助。
2. 用户简历和工作材料上传。
3. 基于材料生成个人画像、项目摘要和专属回答素材。
4. 专属题库和回答模板。
5. 文字或语音模拟面试，用于预演实时辅助场景。
6. 面试音频识别与问题抽取。
7. 实时回答提纲生成。
8. 面试后问题记录与复盘。
9. 基础账号、资料和历史记录能力。

## Out of Scope / Non-goals

第一版明确不做：

1. 自动投递和批量投递。
2. 多招聘平台自动化闭环。
3. 自动代答、自动发言、虚拟人替用户面试。
4. 伪造经历、伪造学历、伪造项目。
5. 多会议平台深度适配。
6. 视频表情、眼神、肢体语言分析。
7. 英文面试，除非后续单独确认。
8. 企业端招聘 SaaS。
9. 绕过会议软件、招聘平台或浏览器安全限制。

## Decision Boundaries

在后续完善 PRD 时，允许代理做以下保守决策：

1. 将第一版定位为“中文线上面试实时辅助 MVP”。
2. 将题库、材料解析、模拟面试定义为实时辅助的支撑模块。
3. 将自动投递、岗位推荐、招聘平台 Agent 后移到后续版本。
4. 将高合规风险能力排除出第一版。
5. 将实时辅助的验收指标写得更具体。
6. 将版本规划按“验证实时辅助 → 增强训练闭环 → 扩展投递闭环”重新排列。

需要用户再次确认的决策：

1. 具体优先支持的会议平台。
2. 是否必须支持系统级音频捕获。
3. 具体技术方案、模型供应商和成本预算。
4. 是否纳入英文场景。
5. 是否要修改原始 PRD 文件而非生成完善版。

## Constraints

1. 必须使用中文场景作为第一版默认范围。
2. 必须避免诱导用户伪造经历。
3. 实时辅助必须由用户主动开启。
4. 产品需要明确提示用户遵守面试平台和招聘方规则。
5. 回答生成应基于用户材料和题库，不应凭空编造关键事实。
6. 第一版功能范围要服务于验证实时辅助是否有用。

## Testable Acceptance Criteria

### Product Acceptance

1. 用户能上传简历或工作材料，并生成可用于实时辅助的个人面试素材。
2. 用户能进入一场模拟线上面试场景。
3. 系统能识别面试官问题，并展示实时回答提纲。
4. 回答提纲能结合用户个人经历，而不是只给通用模板。
5. 面试后能形成问题记录和复盘建议。

### Real-Time Assistance Acceptance

1. 在清晰音频输入下，系统能稳定识别中文面试问题。
2. 多数常见问题能在可接受延迟内返回回答提纲。
3. 回答提纲包含考察点、结构、关键词和建议表达。
4. 用户可以暂停、恢复和结束实时辅助。
5. 系统对不确定识别或信息不足情况有明确提示。

### Safety Acceptance

1. 系统不替用户自动发言。
2. 系统不生成明显虚假的经历。
3. 用户可删除上传材料和历史记录。
4. 面试辅助开启前必须有权限和合规提示。

## Pressure-Pass Findings

原始回答中“A+B 都做原型验证”和“实时辅助达到商业可用”存在潜在冲突。通过后续追问确认：

- 可以保留 A+B，但 B 是主要验证指标。
- A 不需要做成完整题库平台，只需支持 B。
- 自动投递不进入第一版。
- 可以按保守边界完善 PRD。

## Recommended PRD Revision Direction

建议新增或重写以下内容：

1. 将产品一句话定位改为：面向中文线上面试场景的 AI 实时面试辅助产品。
2. 将 MVP 主目标改为：验证实时辅助是否能在模拟/真实线上面试中产生可采纳回答提纲。
3. 将功能优先级调整为：
   - P0：实时辅助、材料解析、个人素材库、基础专属题库。
   - P1：模拟面试、复盘报告、题库练习。
   - P2：岗位推荐、投递话术。
   - P3：自动投递、多平台深度集成、英文场景。
4. 明确第一版非目标，降低合规和工程风险。
5. 增加实时辅助的场景、流程、输入输出、异常状态和验收指标。
