2. 接口详情
2.1 提交简历解析任务
该接口用于上传简历文件并创建解析任务。由于解析过程涉及 OCR 和大模型推理，接口会立即返回任务 ID，客户端需通过任务 ID 查询解析结果。
请求路径：POST /api/v1/resume-parser/tasks
Content-Type：multipart/form-data
请求参数（Form-Data）
请求示例 (cURL)
curl -X POST "https://api.yourdomain.com/api/v1/resume-parser/tasks" \
     -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
     -F "file=@/path/to/resume.pdf" \
     -F "language=zh" \
     -F "remove_noise=true"
成功响应 (HTTP 202 Accepted)
{
  "code": 200,
  "message": "任务提交成功",
  "data": {
    "task_id": "tsk_8f7a9b2c4d1e",
    "status": "PENDING",
    "created_at": "2026-08-05T12:50:00Z"
  }
}

2.2 获取解析结果
根据任务 ID 查询解析状态及结构化数据。
请求路径：GET /api/v1/resume-parser/tasks/{task_id}
Content-Type：application/json
路径参数
请求示例
curl -X GET "https://api.yourdomain.com/api/v1/resume-parser/tasks/tsk_8f7a9b2c4d1e" \
     -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
成功响应 (HTTP 200 OK)

5. 前端联调建议
轮询策略：提交任务后，前端可使用指数退避算法（如 1s, 2s, 4s...）轮询“获取解析结果”接口，直到 status 变为 SUCCESS 或 FAILED。
进度展示：利用 progress 字段（0-100）在前端展示解析进度条，提升用户体验。
原文对照：解析成功后，前端可将 result.resume 中的字段映射到简历编辑器的表单中，并结合原始 PDF 预览实现“点击表单高亮原文”的交互。
