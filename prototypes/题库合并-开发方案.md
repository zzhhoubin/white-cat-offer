# 题库合并 · 开发方案

> 对应需求：`产品需求文档.md`「题库功能调整」  
> 原型：`prototypes/question-bank-unified-prototype.html`

---

## 1. 目标与边界

### 目标

- 取消「通用 / 专属 / 定制」三个 Tab，合并为**单页**。
- 顶部统一筛选：目标岗位、简历&材料、工作年数、是否有 JD（有则页内展开 JD 输入）、「获取面试题」。
- 题目按**来源分页**（**页码条置于结果区下方**，Ant Design 风格：蓝字当前页 / ‹ › / 前往 n 页）：
  1. 系统题库（本地库即时返回）
  2. 简历&材料 LLM（**进入该页才触发**）
  3. JD LLM（有 JD 时；**进入该页才触发**）

### 非目标（本方案不展开）

- 模拟面试出题链路改造（可复用生成结果，但不在本迭代强制改造）
- 题库运营后台 GUI（首期用 CSV/JSON 维护即可）

## 2. 现状摘要

| 能力 | 现状 | 问题 |
|------|------|------|
| 前端 | `QuestionBank.jsx` 三 Tab | 与 PRD 路径不符 |
| 通用题 | `GET /api/question-banks/general` | 实际常走 LLM `generate_general`，非「本地库立刻展示」 |
| 专属题 | `POST .../personal/generate` | 读素材库全文，未按用户勾选简历/材料 |
| 定制题 | `POST .../custom/generate` | 与专属割裂为独立 Tab |
| 存储 | `QuestionBankStore` + DB `QuestionRecord` | 按 bank=general/personal/custom 分桶，可映射到来源页 |

## 3. 信息架构与交互

```
进入题库
  → 选岗位（下拉可自定义）
  → 多选简历 + 材料（简历养成记）
  → 选工作年数
  → 可选：勾选「有目标 JD」→ 页内展开粘贴框
  → 点「获取面试题」
      → 立刻请求系统库 → 展示第 1 页
      → 默认停在第 1 页（不预跑 LLM）
  → 用户点第 2 页 → 触发简历&材料 LLM → loading「快马加鞭」→ 缓存结果
  → 用户点第 3 页（若有 JD）→ 触发 JD LLM → 同上
  → 修改筛选并再次「获取」→ 清空会话缓存，重走第 1 页
```

### 前端状态机（会话级）

```
session = {
  filters: { role, years, resumeIds, materialIds, hasJd, jdText },
  pages: {
    sys:    { status: ready|error, items[] },
    resume: { status: idle|loading|ready|error, items[] },
    jd:     { status: idle|loading|ready|error|skip, items[] }
  },
  activePage: 'sys' | 'resume' | 'jd'
}
```

规则：

- `fetch` 只保证 `sys` 进入 `ready`；`resume/jd` 置 `idle`（无 JD 则 `jd=skip` 且隐藏 Tab）。
- 切换到 `resume/jd` 且 status=`idle` 时发起生成；`loading` 防重复；`ready` 命中缓存。

## 4. 数据与本地题库

### 4.1 系统题库表（建议首期 JSON/CSV，可后续迁 SQLite）

字段（对齐 PRD）：

| 字段 | 说明 |
|------|------|
| `id` | 稳定主键 |
| `role` / `role_aliases` | 目标岗位及别名（匹配「数据分析师」「数据分析」等） |
| `level` / `seniority` | 职级或年数档：`0-1` / `1-3` / `3-5` / `5-10` / `10+` |
| `difficulty` | 初级 / 中级 / 高级 |
| `category` | 行为面 / 技术面 / 场景题 / … |
| `question` | 题干 |
| `answer` | 参考回答（可空，后续 LLM 补） |
| `tags` | 可选关键词 |
| `updated_at` | 维护时间 |

文件建议：`backend/data/system_question_bank.json`（或 `.csv`）。

匹配逻辑（简单可用）：

1. `role` 精确或别名包含  
2. `seniority` 命中年数档（可放宽相邻档）  
3. 按难度/类目抽样，默认返回 8–15 题  
4. 无命中 → 降级同岗位不限年数 → 再降级通用行为面兜底，并前端提示「弱匹配」

### 4.2 用户生成结果缓存

沿用/扩展 `QuestionRecord`：

- `bank`：`sys_snapshot` | `personal` | `custom`（或新增 `source` 字段）
- `meta`：写入本次 `role/years/asset_ids/jd_hash`，便于「同条件复用」

## 5. API 设计（建议）

保持兼容旧接口一段时间，新页优先走统一会话接口。

### 5.1 拉取系统题（第 1 页，即时）

`POST /api/question-banks/session/sys`

```json
{
  "role": "数据分析师",
  "years": "1-3",
  "limit": 12
}
```

响应：`{ ok, questions[], match: "exact"|"weak", count }`  
**禁止**在此接口调用 LLM。

### 5.2 简历&材料生成（第 2 页懒加载）

`POST /api/question-banks/session/from-assets`

```json
{
  "role": "数据分析师",
  "years": "1-3",
  "resume_ids": ["..."],
  "material_ids": ["..."],
  "resume_text": "可选：前端直接传正文",
  "materials": [{ "name": "", "content": "" }]
}
```

说明：简历养成记数据在前端 localStorage 时，首期由前端组装 `resume_text/materials`；后续若上云再改 ID 拉取。

### 5.3 JD 生成（第 3 页懒加载）

`POST /api/question-banks/session/from-jd`

```json
{
  "role": "数据分析师",
  "years": "1-3",
  "jd_text": "..."
}
```

无 JD 时前端不展示第 3 页、不请求。

### 5.4 旧接口

- `general/personal/custom` 暂保留，供模拟面试等调用。
- 新页上线后标记 deprecated，择期删除三 Tab UI。

## 6. SKILL 优化要点

### 6.1 简历&材料 → 题（关键问题 2）

新建/升级：`backend/skills/question_bank/from_assets.md`（或等价 prompt 模块）

必须约束：

- 只依据给定简历+材料，禁止编造项目/数据  
- 题型覆盖：项目深挖、行为、场景、技术（按岗位裁剪）  
- 每题附：考察点、参考回答提纲、关联证据（材料名/简历片段）  
- 输出纯 JSON 数组，题量可配（默认 8）  
- 年数用于控制深挖力度（应届少架构题，高职级多权衡题）

### 6.2 JD → 题（关键问题 3）

新建/升级：`backend/skills/question_bank/from_jd.md`

必须约束：

- 从 JD 抽取硬技能 / 软技能 / 业务场景 / 加分项  
- 生成「JD 高频考点 + 匹配度追问 + 缺口坦诚应答」  
- 不与简历矛盾时不要硬编匹配；可生成「若缺口如何答」类题  
- 无 JD 则整条链路 skip

两套 SKILL 共享 JSON schema，便于前端同一卡片渲染。

## 10. 验收标准

- [ ] 页面无「通用/专属/定制」三个 Tab  
- [ ] 「获取面试题」后 **1s 内**看到第 1 页系统题（不依赖 LLM）  
- [ ] 未点第 2 页时，网络面板无 assets LLM 请求  
- [ ] 点第 2 页出现加载态，完成后可展开参考回答  
- [ ] 未勾选 JD 时无第 3 页；勾选且粘贴后第 3 页懒加载可用  
- [ ] 岗位可自定义输入；简历/材料来自养成记列表  
- [ ] 本地题库可改 JSON 后重启生效（或热加载）  

---

## 11. 风险与决策

| 风险 | 缓解 |
|------|------|
| 本地题库冷启动内容不足 | 先保质量覆盖核心岗位；弱匹配 + 提示 |
| 前端材料仅本地、后端无 ID | P0 前端传正文；注意长度截断 |
| 旧 general 接口仍 LLM | 新 sys 接口隔离；旧接口逐步收敛 |
| 双 LLM 成本/耗时 | 严格懒加载；可加「取消」与超时文案 |

---

## 12. 建议实施顺序

1. 落本地 `system_question_bank.json` + sys API  
2. 改 `QuestionBank.jsx` 对齐原型交互  
3. 接 from-assets / from-jd 懒加载  
4. 抽离并打磨两套 SKILL  
5. 补验收用例与 CHANGELOG  

原型验证通过后，再按 P0 开工实现。
