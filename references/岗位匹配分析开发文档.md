五、模块C：多维度匹配引擎（核心）
功能项：2（匹配得分）、9（多维度评分）、3（优势短板）、10（差距分析）、8（文化适配）
.1 多维度评分体系设计
拒绝简单关键词百分比，采用加权多维评分：

总匹配度 = Σ(维度得分 × 维度权重)

维度权重分配（可根据岗位层级动态调整）：
┌────────────────┬──────────┬──────────┐
│ 维度            │ 初级岗位 │ 高级岗位 │
├────────────────┼──────────┼──────────┤
│ 硬性条件达标    │ 20%      │ 15%      │
│ 核心技能匹配    │ 25%      │ 20%      │
│ 项目经历相关度  │ 20%      │ 25%      │
│ 成果量化质量    │ 15%      │ 20%      │
│ 行业经验匹配    │ 10%      │ 10%      │
│ 企业文化适配    │ 10%      │ 10%      │
└────────────────┴──────────┴──────────┘
.2 各维度评分逻辑
硬性条件匹配（门槛过滤型）：

评分规则：
- 全部满足 → 100分
- 学历不满足 → 直接标记为"高风险"，但允许用户选择继续
- 年限不足但在80%以上 → 60分（可争取）
- 年限不足80% → 30分（强烈不建议）
核心技能匹配（语义理解型）：

评分规则：
- 完全匹配（简历中有明确证据）→ 100分
- 部分匹配（有相关技能但未直接体现）→ 60分
- 可迁移匹配（有类似技能可迁移）→ 40分
- 未体现 → 0分

语义扩展示例：
JD要求"用户增长" → 简历中"拉新""获客""渠道拓展"均视为相关
项目经历相关度（场景匹配型）：

评分规则：
- 业务场景匹配度（行业、业务类型）
- 职责范围匹配度（独立负责 vs 参与协助）
- 规模量级匹配度（团队规模、项目规模）
- 时间近因权重（近3年经历权重更高）
成果量化质量（证据强度型）：

评分规则：
- 有具体数据 + 有对比基准 → 100分
- 有具体数据 + 无对比基准 → 70分
- 有定性描述（"显著提升"）→ 40分
- 无成果描述 → 0分

六、模块D：智能简历重构引擎（核心业务）
功能项：5（经历优先级）、6（优化方案）、12（反向定制）、13（衍生物料）、11（ATS检测）
.1 工作经历优先级排序

排序算法：
优先级得分 = 岗位相关度(40%) + 成果质量(25%) + 时间近因(20%) + 职级匹配(15%)

输出：
- 第一梯队（强相关）：完整展示，重点优化
- 第二梯队（部分相关）：精简展示，突出可迁移部分
- 第三梯队（弱相关）：仅保留基本信息
- 建议隐藏：与目标岗位完全无关且时间久远的经历
.2 反向定制优化流程

Step 1: 确定优化策略
  → 基于匹配分析结果，确定"强化什么、弱化什么、补充什么"

Step 2: 生成优化指令
  → 求职意向重写
  → 个人优势重写（围绕岗位核心需求）
  → 工作经历表达升级（STAR法则 + 数据量化）
  → 技能模块重组（按岗位权重排序）
  → 关键词自然嵌入（融入职责和成果描述）

Step 3: 用户确认
  → 标记所有需要用户确认的事实性内容
  → 区分"表达优化"和"事实补充"

Step 4: 生成优化版简历
  → 输出完整简历 + 逐条修改说明
