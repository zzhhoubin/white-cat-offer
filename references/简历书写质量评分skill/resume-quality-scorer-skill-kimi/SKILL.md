# 简历书写质量评分器

## 概述

本 Skill 对简历的书写质量进行系统化、多维度的专业评分，不仅评估"写了什么"，
更深入评估"怎么写的"——从文档工程、信息架构、表达策略、证据密度、可信度构建
到差异化呈现，全方位诊断简历的竞争力。

评分体系参考 HackerRank hiring-agent 的透明评分理念、Hiration 的 Basic/Proficient/Strong
三级模型，以及业界 HR 的 6 秒筛选法则，确保评分标准既专业又可解释。

## 工作流程

### 阶段一：简历接收与预处理

1. **确认输入**
   - 接收用户上传的简历文件（PDF、DOC/DOCX、图片、TXT、MD）
   - 询问用户是否针对特定岗位（如有 JD，请用户一并提供）
   - 询问用户求职方向/目标岗位级别（初级/中级/高级/管理）
   - 询问用户目标行业（互联网、金融、制造业、咨询等）

2. **内容解析**
   - 提取简历全文内容
   - 识别简历结构（章节、标题、列表、表格）
   - 识别时间线（教育、工作、项目的时间范围）
   - 提取关键信息：姓名、联系方式、技能列表、工作经历、项目经历、教育背景

3. **格式诊断**
   - 判断文件格式（PDF 为佳，DOCX 次之）
   - 识别排版特征（单栏/多栏、字体、字号、页数）
   - 识别是否包含图片、图形、复杂表格（影响 ATS 解析）

### 阶段二：六维度评分

对每个维度按 0-满分 评分，每个分数必须有具体证据支撑。
".\references\dimension-guide.md"提供每个维度的评估方法论、常见陷阱识别和优化策略，评分时参考该方法论，并检查用户简历内容是否存在常见陷阱，并提出优化策略
".\references\scoring-rubric.md"，该文件提供每个维度的精细化评分标准，评分时逐条对照。
#### 维度 1：结构与格式（满分 15 分）

评估简历作为一份专业文档的物理质量。

| 评分等级 | 分值 | 标准 |
|---------|------|------|
| 优秀 | 13-15 | 单栏布局，标准无衬线字体（Arial/Calibri/Aptos），10-12pt 正文，1-2 页，标准章节标题，ATS 完全兼容 |
| 良好 | 10-12 | 布局清晰，字体规范，2 页以内，章节明确，偶有小格式问题但不影响 ATS |
| 合格 | 7-9 | 布局基本清晰，2-3 页，有轻微格式问题（如多栏、非标准标题），ATS 可能部分解析失败 |
| 待改进 | 4-6 | 格式混乱，3 页以上，使用复杂表格/图形，字体不统一，ATS 解析风险高 |
| 不合格 | 0-3 | 排版严重混乱，无法快速定位信息，或格式导致内容无法解析 |

**检查清单**：
- [ ] 是否为单栏布局？（多栏布局 ATS 解析失败率 30%）
- [ ] 是否使用标准无衬线字体 10-12pt？
- [ ] 页数是否在 1-2 页？（应届生 1 页，有经验者 2 页）
- [ ] 章节标题是否标准？（"工作经历"而非"我的旅程"）
- [ ] 列表符号是否标准实心圆点？
- [ ] 是否有足够的留白？（行距 1.15-1.5）
- [ ] 文件格式是否为 PDF？

#### 维度 2：信息完整度（满分 15 分）

评估简历是否包含招聘方期望看到的全部关键信息。

| 评分等级 | 分值 | 标准 |
|---------|------|------|
| 优秀 | 13-15 | 包含所有必备项 + 加分项（GitHub/博客链接、作品集、到岗时间） |
| 良好 | 10-12 | 包含所有必备项，缺少 1 项加分项 |
| 合格 | 7-9 | 缺少 1-2 项必备信息，但不影响基本筛选 |
| 待改进 | 4-6 | 缺少 3 项以上必备信息，或信息位置混乱 |
| 不合格 | 0-3 | 缺少关键信息（如联系方式、教育背景、工作经历） |

**必备项清单**：
- [ ] 姓名
- [ ] 电话
- [ ] 邮箱（专业邮箱，非 partyguy2024@gmail.com 类）
- [ ] 意向岗位（明确写出目标职位）
- [ ] 教育背景（学校、专业、时间）
- [ ] 工作经历（公司、职位、时间、职责描述）
- [ ] 技能列表

**加分项清单**：
- [ ] GitHub/技术博客链接（技术岗）
- [ ] 作品集/项目链接（设计/产品岗）
- [ ] LinkedIn 个人主页
- [ ] 到岗时间/可面试时间
- [ ] 个人简介/Summary（1-2 句话概括核心竞争力）

#### 维度 3：表达质量（满分 20 分）

评估简历内容的语言表达专业度和有效性。

| 评分等级 | 分值 | 标准 |
|---------|------|------|
| 优秀 | 17-20 | 每句以强动词开头，STAR 法则完整，描述具体，无语法错误，句式多样 |
| 良好 | 13-16 | 大部分句子以动词开头，STAR 基本完整，描述较具体，偶有小错误 |
| 合格 | 9-12 | 部分使用动词开头，有 STAR 意识但执行不完整，描述偏概括 |
| 待改进 | 5-8 | 大量使用"负责""参与"等模糊词汇，缺乏具体描述，有明显表达问题 |
| 不合格 | 0-4 | 表达混乱，大量语法错误，或内容像 AI 模板堆砌 |

**强动词清单**（优先使用）：
主导、设计、实现、优化、重构、搭建、部署、推动、协调、
建立、制定、引入、降低、提升、缩短、增长、解决、迁移、
Led, Architected, Implemented, Optimized, Reduced, Improved,
Designed, Deployed, Streamlined, Automated, Spearheaded

**弱动词/模糊词汇**（每出现一次扣 0.5 分，上限 3 分）：
负责、参与、协助、做一些、搞过、弄过、接触过、
Responsible for, Involved in, Assisted with, Helped with,
"some", "a few", "various"

**AI 模板痕迹词汇**（每出现一次扣 0.5 分，上限 3 分）：
赋能、抓手、闭环、底层逻辑、顶层设计、颗粒度、对齐、
组合拳、引爆点、护城河、生态化反、价值转化、
"leverage", "synergy", "holistic", "paradigm", "disruptive"
（在缺乏具体上下文时过度使用）

**STAR 法则检查**：
- **S (Situation)**：是否交代了背景？（如"日活 50 万的电商平台"）
- **T (Task)**：是否明确了任务？（如"需支撑双 11 峰值流量"）
- **A (Action)**：是否描述了你具体做了什么？（如"引入 Redis 缓存 + 限流降级"）
- **R (Result)**：是否有量化结果？（如"接口响应从 500ms 降至 80ms"）

#### 维度 4：量化与证据（满分 20 分）

评估简历中数据支撑的力度和可信度。这是区分"普通简历"和"精英简历"的关键维度。

| 评分等级 | 分值 | 标准 |
|---------|------|------|
| 优秀 | 17-20 | 每段工作经历/项目都有 2+ 个量化指标，数据类型多样，可验证 |
| 良好 | 13-16 | 大部分经历有量化数据，数据类型较丰富 |
| 合格 | 9-12 | 约 50% 经历有量化数据，部分数据类型单一 |
| 待改进 | 5-8 | 少量量化数据，大量使用"大幅提升"等空泛描述 |
| 不合格 | 0-4 | 几乎无量化数据，全是定性描述 |

**量化指标类型识别**：
- **性能类**：QPS、TPS、RT、P99、并发量、吞吐量
- **业务类**：DAU、MAU、GMV、转化率、留存率、收入增长
- **规模类**：用户数、订单量、数据量、服务器数量、团队人数
- **效率类**：开发周期缩短、发布频率提升、自动化率
- **成本类**：服务器成本降低、人力节约、预算控制
- **质量类**：可用性、故障率、Bug 数、代码覆盖率、客诉率

**空洞词汇黑名单**（每出现一次扣 0.5 分，上限 3 分）：
大幅提升、显著优化、明显改进、有效降低、极大提高、
"significantly improved", "greatly enhanced", "substantially reduced",
"effectively streamlined"（无具体数字支撑时）

#### 维度 5：专业可信度（满分 15 分）

评估简历内容的真实感、一致性和专业度。

| 评分等级 | 分值 | 标准 |
|---------|------|------|
| 优秀 | 13-15 | 时间线完全连贯无矛盾，技能与经验高度一致，术语准确，有个人品牌链接 |
| 良好 | 10-12 | 时间线基本连贯，技能与经验一致，术语基本准确 |
| 合格 | 7-9 | 时间线有小问题（如月份模糊），技能与经验部分不一致，偶有不准确术语 |
| 待改进 | 4-6 | 时间线有明显重叠或空白，技能与经验矛盾，术语使用不当 |
| 不合格 | 0-3 | 时间线严重矛盾，明显夸大或虚假信息，大量术语错误 |

**一致性检查清单**：
- [ ] 工作经历时间线是否有重叠？（兼职/实习需说明）
- [ ] 是否有异常长的空白期（>6 个月）未说明？
- [ ] 技能列表中的技术是否在工作/项目中有对应使用证据？
- [ ] 技术术语是否准确？（如"精通"某项技术的证据是否充分）
- [ ] 职位晋升路径是否合理？
- [ ] 教育背景与工作经历时间是否衔接合理？

**可信度信号**（加分）：
- [ ] 提供可验证的链接（GitHub、博客、作品集）
- [ ] 使用具体公司/产品名称（非"某大厂""某知名公司"）
- [ ] 提及具体技术版本（如"Vue 3 + TypeScript"而非"前端框架"）
- [ ] 有明确的汇报关系（"向 CTO 汇报""带 5 人团队"）

#### 维度 6：差异化与亮点（满分 15 分）

评估简历是否能在 6 秒内抓住 HR 注意力，展现独特价值。

| 评分等级 | 分值 | 标准 |
|---------|------|------|
| 优秀 | 13-15 | 有 2+ 个独特亮点，技术深度/业务影响力/领导力至少一项突出 |
| 良好 | 10-12 | 有 1-2 个亮点，在某方面有超出平均水平的展示 |
| 合格 | 7-9 | 亮点不突出，但内容扎实，无明显的"简历同质化"问题 |
| 待改进 | 4-6 | 内容平淡，与其他候选人难以区分，典型的"模板简历" |
| 不合格 | 0-3 | 完全无亮点，内容空洞，像是从招聘网站复制粘贴 |

**亮点识别**：
- **技术深度**：开源项目贡献（merged PR）、技术博客、专利、论文
- **业务影响力**：直接关联营收/成本节约的数据、从 0 到 1 的产品
- **领导力**：带团队经验、跨部门协调、技术决策
- **稀缺性**：罕见技术栈组合、特定领域专家、国际化经验
- **成长性**：快速晋升、跨领域转型成功、持续学习证据

### 阶段三：加分与扣分

#### 加分项（+10 分，逐项累加，上限 10 分）

| 加分项 | 分值 | 说明 |
|-------|------|------|
| 高质量开源贡献 | +3 | GitHub 有 100+ stars 项目，或对知名项目有实质性 merged PR |
| 技术博客/文章 | +2 | 有持续更新的技术博客，或发表过技术文章/演讲 |
| 获奖/专利/论文 | +2 | 技术竞赛获奖、发明专利、学术论文 |
| 多语言能力 | +1 | 除中文外，英语/日语等语言能力有证书或实际应用证据 |
| 特殊经历 | +2 | 创业经历、海外工作/留学、知名公司核心项目 |

#### 扣分项（-10 分，逐项累加，上限 10 分）

| 扣分项 | 分值 | 说明 |
|-------|------|------|
| 拼写/语法错误 | -1/处，上限 -5 | 每处明显错误扣 1 分 |
| 不专业联系方式 | -2 | 如 partyguy2024@gmail.com 类邮箱 |
| 时间线矛盾 | -2 | 工作经历重叠未解释，或明显造假 |
| 敏感信息泄露 | -2 | 包含身份证号、照片（美/欧标准）、婚姻状况等 |
| AI 模板痕迹严重 | -3 | 大量套话、空洞词汇、明显非个人化表达 |
| 过度夸大 | -2 | 技能描述明显超出经验支撑（如应届生"精通分布式架构"） |

### 阶段四：岗位匹配度加权（可选，当提供 JD 时）

如果用户提供了目标岗位 JD，增加岗位匹配度评估（不纳入基础 100 分，作为附加参考）：

| 匹配维度 | 权重 | 评估内容 |
|---------|------|---------|
| 技能匹配 | 40% | 简历技能与 JD 要求技能的覆盖度 |
| 经验匹配 | 30% | 工作经历与 JD 职责描述的契合度 |
| 行业匹配 | 20% | 行业背景与目标岗位的关联度 |
| 级别匹配 | 10% | 当前经验级别与 JD 要求级别的匹配度 |

**岗位匹配度得分**：0-100 分，单独输出，不与书写质量分合并。

### 阶段五：报告生成

".\assets\score-report-template.md"该文件定义标准评分报告的输出格式，输出结构化评分报告时引用该文件内容，结构化评分报告包含：

1. **总分与等级**
2. **六维度雷达图**（文字描述）
3. **各维度得分与证据**
4. **加分/扣分明细**
5. **TOP 3 优势**
6. **TOP 3 待改进项**（按影响优先级排序）
7. **具体修改建议**（逐条给出可执行建议）
8. **岗位匹配度**（如有 JD）


## 评分等级定义

| 等级 | 分数范围 | 含义 |
|------|---------|------|
| 优秀 (Elite) | 90-110 | 简历本身即为加分项，可直接投递顶级公司 |
| 良好 (Strong) | 75-89 | 有竞争力，少量针对性优化即可进入面试环节 |
| 合格 (Proficient) | 60-74 | 基本可用，但在激烈竞争中容易被淹没，需重点优化 |
| 待改进 (Developing) | 40-59 | 存在明显问题，建议按报告逐项重写 |
| 不合格 (Needs Work) | 0-39 | 结构或内容存在严重缺陷，建议重新构建 |

## 边界情况处理

| 场景 | 处理策略 |
|-----|---------|
| 简历为图片且 OCR 质量差 | 告知用户图片解析受限，建议提供 PDF/Word 版本，基于可识别内容评分并标注不确定性 |
| 简历使用非标准模板（如设计岗创意简历） | 调整"结构与格式"维度评分标准，允许创意排版，但评估信息可读性和 ATS 兼容性 |
| 应届生简历缺少工作经历 | 调整权重：降低"工作经历"相关评分权重，提高"项目经历"和"教育背景"权重 |
| 简历为英文 | 使用英文版评分标准，术语检查切换为英文语境 |
| 用户提供多份简历 | 分别评分，提供对比分析和最优版本建议 |
| 简历内容涉密 | 提醒用户脱敏，评分时不记录敏感信息 |
| 用户要求只关注某维度 | 聚焦该维度深度分析，其他维度简要评分 |

## 注意事项

1. **客观性**：评分必须基于简历实际内容，不得因个人偏好调整标准
2. **可解释性**：每个分数必须有具体证据支撑，避免"我觉得"式评价
3. **建设性**：批评必须附带可执行的改进建议，而非仅指出问题
4. **文化适配**：中文简历和英文简历的评分侧重点不同（中文重全面性，英文重简洁和影响力）
5. **行业适配**：技术岗重项目深度和数据，管理岗重团队规模和业务影响，创意岗重作品集
6. **隐私保护**：不存储、不传播简历内容，评分完成后仅保留报告摘要
7. **避免偏见**：不因学校、公司名气加分或减分，只看内容质量
