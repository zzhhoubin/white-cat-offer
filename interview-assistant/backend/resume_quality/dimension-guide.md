# 各维度评估指南

本文件提供每个维度的评估方法论、常见陷阱识别和优化策略。

---

## 维度 1：结构与格式

### 评估方法论

1. **6 秒测试**：模拟 HR 快速扫描，能否在 6 秒内定位到：姓名、意向岗位、最近一段工作经历、核心技能？
2. **F 型视觉流**：人类阅读简历呈 F 型（先扫顶部横线，再扫左侧竖线）。关键信息是否落在 F 型热点区？
3. **ATS 模拟**：判断简历被机器解析时，章节标题是否能正确映射到标准字段。

### 常见陷阱

| 陷阱 | 问题 | 影响 |
|------|------|------|
| 多栏布局 | ATS 解析时可能将右栏内容拼接错乱 | 信息丢失或错位 |
| 图片/图标替代文字 | 电话图标无 alt 文本 | 联系方式无法提取 |
| 非标准标题 | "我的成长"代替"工作经历" | ATS 无法识别章节 |
| 页边距过窄 | < 0.5 英寸 | 打印时内容被截断 |
| 过度设计 | 色块、图形、渐变背景 | 分散注意力，ATS 不友好 |

### 优化策略

- **单栏 + 标准字体**：最安全的选择，兼容性 100%
- **信息层级**：姓名（最大）→ 意向岗位 → 工作经历 → 技能 → 教育
- **留白法则**：行距 1.15-1.5，段间距大于行间距，页边距 ≥ 0.7 英寸
- **PDF 优先**：DOCX 在不同版本 Word 中可能排版错乱

## 维度 2：信息完整度

### 评估方法论

1. **必备项扫描**：逐项检查 5 大必备信息是否存在
2. **信息位置检查**：关键信息是否在 F 型阅读路径上
3. **附加价值识别**：是否有超越基础信息的增值内容

### 常见陷阱

| 陷阱 | 问题 | 影响 |
|------|------|------|
| 缺少意向岗位 | HR 不知道你想投什么 | 直接筛掉 |
| 联系方式不全 | 只有邮箱无电话，或反之 | 沟通障碍 |
| 教育背景缺失时间 | 无法判断毕业年限 | 无法评估经验级别 |
| 工作经历无描述 | 只有公司+职位，无职责 | 无法评估能力 |
| 技能列表过长 | 列出 30+ 项技能 | 稀释重点，显得浮躁 |

### 优化策略

- **意向岗位前置**：放在姓名下方，让 HR 第一眼知道你的目标
- **技能分层**：核心技能（精通）→ 熟练技能 → 了解技能，控制在 10-15 项
- **附加信息策略**：技术岗放 GitHub，设计岗放作品集，管理岗放 LinkedIn
- **到岗时间**：如有明确时间，标注可增加筛选通过率

## 维度 3：表达质量

### 评估方法论

1. **动词审计**：逐句检查句首动词强度
2. **STAR 扫描**：对每段经历进行 S-T-A-R 四要素检查
3. **具体性测试**：将描述中的技术名词替换为"某技术"，看是否仍成立。若成立，则描述不够具体。

### 常见陷阱

| 陷阱 | 示例 | 问题 |
|------|------|------|
| "负责"陷阱 | "负责前端页面开发" | 被动、无主动性 |
| 无结果描述 | "使用 React 开发后台管理系统" | 做了什么，但效果如何？ |
| 过度概括 | "优化了系统性能" | 无具体技术/数据 |
| AI 模板痕迹 | "赋能业务增长，抓手是用户体验" | 套话，无实质内容 |
| 主语混乱 | "项目使用了微服务架构" | 未说明"我"做了什么 |

### 优化策略：STAR-R 模型

在标准 STAR 基础上增加 **R (Replicability/复用性)**：

```
❌ 弱表达：
"负责公司官网的前端开发，使用 Vue.js 框架。"

✅ 强表达：
"主导公司官网前端重构（S）：原官网加载慢、SEO 差，影响获客；
 任务是将加载时间控制在 2s 内并提升搜索排名（T）；
 选型 Vue 3 + Nuxt 3 实现 SSR，引入图片懒加载和 CDN 加速（A）；
 首屏加载从 5.2s 降至 1.4s，SEO 收录量提升 180%，
 该方案后被推广至 3 个子站复用（R）。"
```

### 动词升级对照表

| 弱动词 | 升级后 |
|--------|--------|
| 负责 | 主导、统筹、推进 |
| 参与 | 贡献、协作、配合 |
| 使用 | 选型、引入、落地 |
| 做了 | 设计、实现、搭建 |
| 优化 | 重构、精简、提速 |
| 管理 | 带领、培养、协调 |

## 维度 4：量化与证据

### 评估方法论

1. **数字扫描**：提取简历中所有数字，分类统计
2. **密度计算**：数字出现次数 / 总 bullet point 数
3. **类型多样性**：识别数字所属的指标类型
4. **可信度验证**：大数字是否有上下文支撑

### 常见陷阱

| 陷阱 | 示例 | 问题 |
|------|------|------|
| 无基数的百分比 | "效率提升 200%" | 从什么提升到什么？ |
| 不可验证的大数字 | "服务 10 亿用户" | 个人贡献 vs 团队/公司产品 |
| 单一指标类型 | 所有项目都是"提升 X%" | 缺乏维度多样性 |
| 虚假精确 | "响应时间 127.38ms" | 过度精确反而可疑 |
| 无数字 | 全文无一个数字 | 无法评估影响力 |

### 优化策略：量化公式

每个 bullet point 尽量包含：**动作 + 技术/方法 + 数字 + 结果**

```
公式：
[强动词] + [具体技术/方法] + [量化指标] + [业务影响]

示例：
"引入 Redis 缓存 + 数据库读写分离，接口 P99 从 800ms 降至 120ms，
 支撑日订单量从 10 万增至 50 万，服务器成本降低 40%。"
```

### 各岗位量化重点

| 岗位类型 | 重点量化指标 |
|---------|-------------|
| 后端开发 | QPS/TPS、RT/P99、可用性、服务器成本 |
| 前端开发 | 首屏时间、Lighthouse 分数、转化率提升、组件复用数 |
| 算法/数据 | 模型准确率、AUC 提升、推理延迟、数据规模 |
| 产品经理 | DAU/留存、GMV、功能使用率、需求交付周期 |
| 运营 | 活动 ROI、用户增长、内容产出量、转化率 |
| 管理岗 | 团队规模、项目交付率、人效提升、预算控制 |

## 维度 5：专业可信度

### 评估方法论

1. **时间线重构**：按时间顺序排列所有经历，检查重叠和空白
2. **技能-经验映射**：将技能列表与项目/工作经历做交叉验证
3. **术语核查**：检查技术术语的准确性和一致性
4. **可验证性评估**：是否有外部链接或具体信息可供验证

### 常见陷阱

| 陷阱 | 示例 | 问题 |
|------|------|------|
| 时间重叠 | 2020.03-2022.06 公司 A 全职 + 2020.06-2021.12 公司 B 全职 | 未解释如何同时全职 |
| 技能膨胀 | 应届生列出 20+ 项"精通"技能 | 可信度极低 |
| 术语误用 | "精通机器学习"但只调过包 | 面试一问即破 |
| 模糊公司名 | "某知名互联网公司" | 无法验证，显得心虚 |
| 过度包装 | "CTO"但公司只有 3 人 | 职级与规模不匹配 |

### 优化策略

- **诚实分层**：熟练度用"精通/熟练/了解"三级，且"精通"不超过 3 项
- **时间线透明**：有重叠注明"兼职""实习"，有空白期可写"技能提升/个人项目"
- **具体化**：用公司实名，用技术版本号，用具体团队规模
- **可验证链接**：GitHub、博客、作品集是最佳可信度背书

## 维度 6：差异化与亮点

### 评估方法论

1. **同质化检测**：将简历中的公司名、项目名替换为通用词，看是否仍像一份"标准简历"
2. **亮点扫描**：识别 3 秒内能抓住注意力的独特信息
3. **深度探测**：检查是否有至少一段经历展示了超越"使用某技术做某功能"的深度

### 常见陷阱

| 陷阱 | 示例 | 问题 |
|------|------|------|
| 简历同质化 | 与 100 份同岗位简历 80% 内容可互换 | 无记忆点 |
| 罗列技术栈 | 只写"会用 React/Vue/Angular" | 无深度 |
| 无个人视角 | "团队完成了项目" | 你的独特贡献是什么？ |
| 亮点埋藏 | 最有价值的经历放在最后 | HR 可能看不到 |
| 虚假亮点 | "全国大学生XX比赛一等奖"但查无此赛 | 诚信问题 |

### 优化策略

- **倒金字塔结构**：将最有价值的经历放在最前面
- **独特卖点（USP）提炼**：
  - 技术深度："从零设计并实现了公司的 CI/CD 流水线"
  - 业务影响："主导的功能上线后贡献季度营收的 15%"
  - 稀缺组合："全栈 + 算法背景，能独立完成 AI 产品全链路"
- **个人简介**：用 1-2 句话概括你的独特价值，放在姓名下方

## 跨文化适配指南

### 中文简历特点

- 允许更全面的信息展示（1-2 页均可）
- 可包含政治面貌（国企/公务员需要）
- 技能列表可以更详细
- 项目经历通常需要更完整的背景描述

### 英文简历特点

- 极度简洁，1 页为黄金标准（有经验者最多 2 页）
- 禁止包含：照片、年龄、婚姻状况、宗教信仰
- 强调动词开头和量化结果
- Summary 部分非常重要（替代中文简历中的"自我评价"）
- 使用美式拼写（color 而非 colour）或统一英式

### 日文简历特点

- 通常使用固定格式（履歴書）
- 需要照片
- 强调学历和时间线的完整性
- 技能描述偏保守，"精通"很少使用
