# 详细评分量规

本文件提供每个维度的精细化评分标准，供评分时逐条对照。

---

## 维度 1：结构与格式（15 分）

### 布局与排版（5 分）

| 分值 | 标准 |
|------|------|
| 5 | 单栏布局，F 型视觉流，信息层级清晰，留白充足 |
| 4 | 单栏为主，偶有小区域双栏（如技能列表），不影响整体阅读 |
| 3 | 双栏布局，但核心信息在左栏，ATS 可解析主要内容 |
| 2 | 多栏/网格布局，信息分散，阅读流被打断 |
| 1 | 布局混乱，无明确信息层级，难以快速定位内容 |
| 0 | 无法解析布局（如扫描件、图片简历无 OCR） |

### 字体与字号（3 分）

| 分值 | 标准 |
|------|------|
| 3 | 标准无衬线字体（Arial/Calibri/Aptos/Helvetica），正文 10-11pt，标题 14-16pt |
| 2 | 字体规范，但字号略大（12pt+正文）或略小（<10pt正文） |
| 1 | 使用衬线字体（Times New Roman 等，非创意岗），或字号极端 |
| 0 | 字体花哨（手写体、艺术字），严重影响可读性 |

### 页数控制（3 分）

| 分值 | 标准 |
|------|------|
| 3 | 应届生 1 页，有经验者 2 页，内容密度适中 |
| 2 | 2 页但第二页内容不足半页，或 1 页但信息过载 |
| 1 | 3 页，存在可删减的冗余内容 |
| 0 | 3 页以上，或 1 页内严重信息缺失 |

### ATS 兼容性（4 分）

| 分值 | 标准 |
|------|------|
| 4 | PDF 格式，纯文本可提取，无复杂表格/图片/图形，标准章节标题 |
| 3 | PDF 格式，有简单表格（如技能矩阵），但主要内容可解析 |
| 2 | DOCX 格式，或 PDF 中有图片/图标替代文字 |
| 1 | 使用非标准标题（如"我的成长"代替"工作经历"），ATS 无法映射 |
| 0 | 图片格式、扫描件、或包含大量图形元素导致文本无法提取 |

## 维度 2：信息完整度（15 分）

### 必备信息（10 分）

每项 2 分，共 5 项核心必备信息：
1. 姓名 + 联系方式（电话 + 专业邮箱）
2. 意向岗位（明确的职位名称）
3. 教育背景（学校、专业、学位、时间）
4. 工作经历/项目经历（至少一段，含公司/项目名、角色、时间、描述）
5. 技能列表（与技术岗相关，或与管理岗相关的核心能力）

### 信息架构（3 分）

| 分值 | 标准 |
|------|------|
| 3 | 信息按重要性排序（姓名→意向→经历→技能→教育），符合 HR 阅读习惯 |
| 2 | 信息完整但排序稍差（如教育背景放在工作经历之前，对有经验者不利） |
| 1 | 信息位置混乱（如联系方式在页脚，技能列表分散在各处） |
| 0 | 信息完全无组织，HR 无法在 6 秒内定位关键内容 |

### 附加信息（2 分）

| 分值 | 标准 |
|------|------|
| 2 | 包含 2 项以上加分项（GitHub、博客、作品集、LinkedIn、到岗时间） |
| 1 | 包含 1 项加分项 |
| 0 | 无任何附加信息 |

## 维度 3：表达质量（20 分）

### 动词强度（6 分）

统计每段经历描述中的句子：
- 强动词开头比例 ≥ 80%：6 分
- 强动词开头比例 60-79%：4-5 分
- 强动词开头比例 40-59%：2-3 分
- 强动词开头比例 < 40%：0-1 分

**强动词示例**：
主导、设计、实现、优化、重构、搭建、部署、推动、协调、
建立、制定、引入、降低、提升、缩短、增长、解决、迁移、
Led, Architected, Implemented, Optimized, Reduced, Improved,
Designed, Deployed, Streamlined, Automated, Spearheaded, Engineered

**弱动词示例**：
负责、参与、协助、做一些、搞过、弄过、接触过、
Responsible for, Involved in, Assisted with, Helped with,
Worked on, Participated in

### STAR 法则完整度（6 分）

对每段核心经历进行 STAR 检查：

| 分值 | 标准 |
|------|------|
| 6 | 80% 以上经历完整包含 S-T-A-R 四要素 |
| 4-5 | 60-79% 经历完整，其余缺少 1 个要素（通常是 S 或 T） |
| 2-3 | 40-59% 经历完整，普遍存在缺少 S/T/R 的情况 |
| 0-1 | < 40% 经历完整，大部分只有 A 或只有 A+R 的简单描述 |

### 描述具体性（4 分）

| 分值 | 标准 |
|------|------|
| 4 | 每段描述都包含具体技术/方法/工具/场景，无空泛概括 |
| 3 | 大部分描述具体，偶有空泛句子 |
| 2 | 约半数描述具体，存在"使用相关技术解决问题"类模糊表述 |
| 1 | 大部分描述空泛，缺乏具体技术或方法 |
| 0 | 完全空泛，如"完成了相关工作" |

### 语法与拼写（4 分）

| 分值 | 标准 |
|------|------|
| 4 | 零错误 |
| 3 | 1-2 处轻微错误（如标点、大小写） |
| 2 | 3-5 处错误 |
| 1 | 6-10 处错误 |
| 0 | 10 处以上错误，或存在严重语法问题影响理解 |

## 维度 4：量化与证据（20 分）

### 数据密度（8 分）

统计所有工作经历和项目经历的 bullet point 数量，以及其中包含数字的比例：

| 分值 | 标准 |
|------|------|
| 8 | ≥ 70% 的 bullet points 包含具体数字 |
| 6-7 | 50-69% 包含数字 |
| 4-5 | 30-49% 包含数字 |
| 2-3 | 10-29% 包含数字 |
| 0-1 | < 10% 包含数字 |

### 数据类型多样性（6 分）

识别简历中出现的量化指标类型数量（见下方类型列表）：

| 分值 | 标准 |
|------|------|
| 6 | 包含 5 种以上不同类型的量化指标 |
| 4-5 | 包含 3-4 种类型 |
| 2-3 | 包含 1-2 种类型 |
| 0-1 | 仅重复同类型指标（如只有"提升 X%"） |

**量化指标类型**：
1. 性能类（QPS、RT、P99、并发）
2. 业务类（DAU、GMV、转化率、收入）
3. 规模类（用户数、数据量、团队人数）
4. 效率类（周期缩短、自动化率）
5. 成本类（节约金额、资源优化）
6. 质量类（可用性、故障率、覆盖率）

### 可验证性（4 分）

| 分值 | 标准 |
|------|------|
| 4 | 所有关键数据都有上下文支撑，逻辑合理，无夸张嫌疑 |
| 3 | 大部分数据可信，偶有大数字但背景合理 |
| 2 | 部分数据缺乏上下文（如"提升 1000%"但无基数说明） |
| 1 | 存在明显夸张数据（如应届生"管理 100 人团队"） |
| 0 | 数据明显虚假或无法自洽 |

### 避免空洞词汇（2 分）

检查是否过度使用无数字支撑的形容词：

| 分值 | 标准 |
|------|------|
| 2 | 零空洞词汇 |
| 1 | 1-3 处空洞词汇 |
| 0 | 4 处以上空洞词汇 |

**空洞词汇清单**：
大幅提升、显著优化、明显改进、有效降低、极大提高、
很好地、成功地、顺利地、出色地、全面地、深入地、
significantly, greatly, substantially, effectively, successfully
（无具体数字支撑时）

## 维度 5：专业可信度（15 分）

### 时间线一致性（5 分）

| 分值 | 标准 |
|------|------|
| 5 | 时间线完全连贯，教育→工作衔接合理，无重叠或异常空白 |
| 4 | 有小重叠但已注明（如兼职、实习），或 3 个月内空白 |
| 3 | 有未解释的重叠，或 3-6 个月空白 |
| 2 | 有 6-12 个月空白未说明 |
| 1 | 时间线严重矛盾（如 2020-2022 同时两段全职工作未解释） |
| 0 | 时间线完全混乱，无法判断 |

### 技能-经验一致性（4 分）

| 分值 | 标准 |
|------|------|
| 4 | 技能列表中的每项技术都在工作/项目中有具体使用证据 |
| 3 | 大部分技能有使用证据，少数技能（<20%）无直接证据 |
| 2 | 约半数技能有使用证据 |
| 1 | 大量技能（>50%）仅列在技能栏但无项目/工作支撑 |
| 0 | 技能与经验完全脱节 |

### 术语准确性（3 分）

| 分值 | 标准 |
|------|------|
| 3 | 所有技术术语使用准确，无混淆（如区分"并发"与"并行"） |
| 2 | 偶有不准确但非关键术语 |
| 1 | 有明显术语误用（如"精通机器学习"但只用过 sklearn 调包） |
| 0 | 大量术语错误，暴露技术理解浅薄 |

### 可信度信号（3 分）

| 分值 | 标准 |
|------|------|
| 3 | 有可验证链接 + 具体公司名 + 具体技术版本 |
| 2 | 有其中 2 项 |
| 1 | 有其中 1 项 |
| 0 | 无可验证信息，全用"某大厂""某知名项目"等模糊表述 |

## 维度 6：差异化与亮点（15 分）

### 独特性（5 分）

| 分值 | 标准 |
|------|------|
| 5 | 有 2+ 个在同龄/同级候选人中罕见的经历或技能组合 |
| 4 | 有 1 个独特亮点 |
| 3 | 内容扎实但无特别突出之处 |
| 2 | 内容普通，与模板简历高度相似 |
| 1 | 完全同质化，看不出个人特色 |
| 0 | 内容空洞，像是从招聘网站复制粘贴 |

### 深度展示（5 分）

| 分值 | 标准 |
|------|------|
| 5 | 至少一段经历展示了技术/业务深度（架构设计、性能调优、业务策略） |
| 4 | 有深度但展示不够充分 |
| 3 | 有技术细节但停留在使用层面 |
| 2 | 仅描述功能实现，无技术决策或难点攻克 |
| 1 | 仅罗列技术栈，无实际应用描述 |
| 0 | 无技术/业务深度内容 |

### 影响力呈现（5 分）

| 分值 | 标准 |
|------|------|
| 5 | 明确展示了个人对团队/产品/业务的实质性影响（带数据） |
| 4 | 展示了影响但数据不足 |
| 3 | 有团队角色描述但无影响数据 |
| 2 | 仅描述参与角色，无影响说明 |
| 1 | 无团队/影响相关内容 |
| 0 | 完全个人视角，无组织协作意识 |

## 加分项（+10 分上限）

| 项目 | 分值 | 判定标准 |
|------|------|---------|
| 开源贡献 | +3 | GitHub 有 100+ stars 项目，或对知名开源项目有 merged PR |
| 技术博客 | +2 | 有持续更新（近 1 年有 3+ 篇）的技术博客/公众号 |
| 获奖/专利 | +2 | 省级以上竞赛获奖、发明专利、核心期刊论文 |
| 演讲/分享 | +2 | 在技术会议/公司内部分享过技术主题 |
| 多语言能力 | +1 | 英语流利（有雅思/托福成绩或外企工作经历），或其他语言 |
| 特殊经历 | +2 | 创业（无论成败）、海外工作/留学、知名公司核心项目 |

---

## 扣分项（-10 分上限）

| 项目 | 分值 | 判定标准 |
|------|------|---------|
| 拼写/语法错误 | -1/处，上限 -5 | 每处明显错误 |
| 不专业邮箱 | -2 | 如 cutebaby@qq.com、partyguy2024@gmail.com 等 |
| 时间线矛盾 | -2 | 未解释的 overlapping full-time jobs，或明显造假 |
| 敏感信息 | -2 | 身份证号、照片（美/欧标准）、婚姻状况、宗教信仰、政治面貌 |
| AI 模板痕迹 | -3 | 大量套话、空洞词汇、明显非个人化表达 |
| 过度夸大 | -2 | 技能描述明显超出经验支撑 |
| 格式错误 | -1 | 如使用.doc 格式、文件名不规范（"简历最终版_真的最终版.pdf"） |
